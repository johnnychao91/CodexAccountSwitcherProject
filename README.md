# Codex 帳號切換器

Windows 原生、繁體中文的本機帳號管理小工具。使用 Windows 10 / 11 x64 與 .NET Framework 4.8，無須安裝 Python、Node.js 或額外套件。從 GitHub 取得原始碼後，雙擊根目錄的「Codex帳號切換器.cmd」即可開啟；若缺少執行檔或設定檔，啟動器會先自動建置。也可手動執行 `powershell -ExecutionPolicy Bypass -File .\build.ps1`，再開啟 `dist-v1.6.0\CodexAccountSwitcher.exe`。

## 新電腦開始使用

1. 使用 Windows 10 / 11 x64、.NET Framework 4.8，並先安裝官方 Codex 桌面 App。
2. `git clone` 此專案後，雙擊 `Codex帳號切換器.cmd`。第一次會自動建置；不需要安裝 Visual Studio、Node.js 或 Python，也不用填寫本機路徑。
3. 在新電腦重新登入並加入帳號。本機加密帳號庫不會隨 Git 複製，也不能直接從另一台電腦搬過來。

需要自動切換與續聊時，開啟自動監看、桌面控制及桌面續聊。若 Codex 已在執行，先完成目前工作，再正常 Quit 一次，由切換器建立受管連線。桌面控制依賴 Codex 版本相容性；可選的 Local Work 封鎖另有版本檢查。

## v1.5.5：多版本自動續聊相容性

自動續聊改用獨立的相容性設定，保留已檢查的 26.1021.3705.0 套件，並加入 26.1027.3384.0。套件指紋與原對話、受管程序、權限、一次送出等檢查仍保留；未知或被修改的套件會停止續聊。Local Work 封鎖使用自己的版本限制，不會因續聊相容性新增而放寬。

新版的對話尋找、中止與開始回合協定版本仍為 1、4、2。已從真正 App 套件擷取分派函式，使用合成對話驗證原回合中止、原設定轉送、擁有者拒絕與失敗不重送；沒有操作真實 App。真實帳號耗盡後跨帳號重開與續聊，仍需實機確認。主畫面的續跑狀態現在使用這個獨立檢查。

開發驗證可執行 `node .\tests\Test-ContinuationProtocol.js <已安裝套件的 app.asar 路徑>`；此測試只讀取已核對指紋的套件並使用合成對話，不連線或啟動 App。一般使用不需要 Node.js。

## v1.5.4：自動續跑開關

主畫面提供「開啟自動續跑／關閉自動續跑」按鈕，取代原本的勾選框，並保存開關選擇。按鈕只控制額度耗盡後的自動續跑，不會立即送出訊息。旁邊分別顯示功能開關、版本是否通過驗證，以及是否仍等待自動監看或桌面連線；版本未通過時，即使設定開啟也不會自動續跑。按「檢查工作狀態」可重新檢查版本相容性。

修正連線代理錯用 Local Work 封鎖的舊版套件雜湊檢查，導致新版 Codex 在受管啟動時可能顯示「無法載入組織設定」。一般代理啟動仍核對套件、後端與程序歸屬；Local Work 封鎖及自動續聊的版本驗證各自保留。新版 App 尚未通過這些進階功能驗證時，不能將成功啟動視為進階功能已相容。

## v1.5.2：新電腦桌面連線與錯誤診斷

修正 Windows PowerShell 讀取桌面啟動設定時的文字編碼，讓中文及其他非英文的使用者名稱、專案與資料路徑保持完整。新建的私人資料夾及中繼資料也會明確指定目前 Windows 使用者為擁有者；既有資料仍需通過私人權限檢查。

讀寫或桌面連線失敗時，畫面會顯示錯誤代碼，並嘗試在 `%LOCALAPPDATA%\CodexAccountSwitcher\diagnostics\last-error.json` 保存一筆診斷。診斷只含操作分類、代碼及程式內部來源，不記錄登入憑證、聊天內容或本機路徑。若需要協助，可提供新版畫面上的代碼。

## v1.5.1：額度全部耗盡後等待重置並續跑

開啟自動監看、桌面控制與桌面續聊後，若目前帳號額度耗盡、找不到其他可用帳號，而且原對話已被 Codex 確認因額度限制中止，切換器會顯示「等待額度重置」。等待期間每 60 秒查詢額度；較高優先級與目前帳號都恢復時，選擇其中順位最高的可用帳號。若只有目前帳號恢復，就保留目前登入。只提供每週上限的帳號仍依每週額度判斷；不會只憑重置時間已到就認定可用。

恢復額度後會再次核對等待中的原對話及設定。兩種情況都正常關閉受管 App、重開原對話，再送出一次 `繼續執行`；保留目前帳號時不改寫登入資料。等待期間不鎖住 App，也不對已被額度中止的回合重複送出中止要求。切換器需要保持開啟才能輪詢；重新開啟切換器時，只恢復尚未開始續跑的等待記錄，送出結果不明的操作不重送。

關閉監看或桌面續聊、手動操作帳號，會取消等待。若使用者已手動續聊或原對話狀態變更，也不會再接續舊回合。此功能沿用桌面控制的程序與對話驗證；未受管程序或其他忙碌工作仍會等待正常結束。

## v1.5.0：額度耗盡後在原桌面對話續聊

同時開啟「自動監看並切換」、桌面控制與「額度耗盡時正常中止桌面對話，切換後送出一次『繼續執行』」後，目前帳號確認耗盡時，會依手動排序尋找第一個已確認有額度的帳號。工具保存原對話及模型、推理強度、工作目錄和權限設定，正常中止目前回合，等後端與 App 正常退出，再切換登入、重開原對話並送出 `繼續執行`。已因額度限制失敗的回合不會再次中止；閒置且沒有待接續工作時，只切換並開啟 App。手動切換帳號不會自動送出訊息。

桌面續聊選項預設開啟並記住選擇，自動額度監看仍須自行開啟。更新後請先完成目前工作並正常 Quit 一次，再由新版切換器開啟 Codex，建立新版桌面控制連線。舊連線不能直接升級。新版以原生連線代理保留 App 自己的對話管理介面，仍由受管 Host 負責後端、狀態核對與正常退出，無須安裝額外執行環境。

每次續聊在送出前先保存加密的一次性記錄，轉送端也只接納相同操作的一次要求。收到確認後才標示已續聊；若逾時、程式中斷、帳號或對話狀態改變，會停止自動送出並提示檢查原對話。重新開啟切換器不會重送不確定的訊息。這避免重複執行，但不能保證每次不確定的送出都已被 Codex 接收；可先查看原對話再決定是否手動繼續。

此版限單一可驗證的本機持久對話；無法完整保留的計畫模式、停用外掛清單或其他特殊工具設定會停止自動續聊。多個進行中的主對話、遠端或暫存對話、未結束的背景工作、執行中或狀態不明的自主目標、無法辨識的 App 版本，以及未受管的 IDE／CLI 會阻擋自動接續。VS Code 仍使用獨立整合與原有中止選項，不會自動發送續聊訊息。正常中止不會撤銷之前已完成的檔案或外部操作。

受管模式目前不支援 App 內需要獨立執行器的瀏覽器工具；需要使用時，請關閉桌面控制並正常重開為一般模式。Local Work 沿用原有開關；未封鎖時的獨立工作程序仍會阻擋切換。

驗證範圍：已用隔離 App 驗證原對話中止，以及換假帳號後在同對話送出一次訊息和防重送。最新版正常退出等待修正已通過背景回歸，活動來源至目標的完整自動串接仍待實機驗收；詳見[驗證紀錄](docs/runtime-control-validation.md)。

## v1.4.13：避免桌面狀態查詢互相排隊

桌面背景輪詢與即時查詢重疊時，改為共用同一個進行中的唯讀查詢，完成後下一次仍重新查詢。準備與正常退出操作不共用結果，保留原有閒置、程序身分與授權檢查。查詢逾時或失敗會顯示具體原因，不再誤顯示為使用者已停用控制。

切換等待時會在本機私人整合目錄保存最多 32 筆匿名阻擋原因，便於核對桌面、VS Code 及未受管程序；不含帳號、對話、命令、執行檔路徑或 PID。VS Code 的自動暫停仍須先安裝並啟用「VS Code 整合」。

## v1.4.12：開啟 App 時建立桌面控制連線

連線後，自動切換帳號沿用原有閒置檢查、正常退出、套用帳號及重新開啟流程。首次準備連線與切換器開啟時的自動接續維持；平常 Quit 後可按「開啟 Codex App」再次連線。

桌面控制開啟且已連線時使用綠色實心按鈕；開啟但未連線時使用綠色外框；關閉時使用紅色外框。工作狀態每十秒唯讀更新，無法確認連線時保持外框顯示。開關記憶、自動啟動及切換前的工作檢查維持原本行為。

## v1.4.8：記住桌面控制開關並自動接續啟動

主畫面會明確顯示桌面控制「已開啟／已關閉」，連線狀態另行顯示。開關已開啟只表示希望啟用自動控制；「待開啟受管桌面」「等待正常 Quit」「已連線，忙碌」與「已連線，閒置」仍是不同狀態，不能把開啟設定當成已可切換帳號。

首次使用或尚無控制授權、也未保存開關選擇的設定，桌面控制預設開啟。工具會保存選擇，之後重新開啟時自動確認受管桌面狀態並接續啟動；先前已明確停用的設定則沿用關閉。可在「桌面控制…」勾選或取消「開啟桌面自動控制（記住此設定）」。自行關閉後，重新開啟切換器也不會再次自動啟用。

若已有可驗證的受管桌面連線，沿用該連線；若一般 Codex、舊版協調器或其他相關程序仍開著，顯示等待正常退出，不會強制結束或再開一個桌面實例。完成工作並正常 Quit 後，須確認所有相關程序及記錄中的活程序都已退出，才會沿用首次啟用的檢查開啟受管桌面。設定無法讀取或格式不正確時，不會以預設開啟覆蓋未知狀態。

切換帳號仍須通過可靠的工作狀態、閒置、正常退出與程序身分檢查；Local Work 封鎖的版本驗證也維持。重新開啟切換器不會自動切換帳號或重送聊天訊息。

## v1.4.7：桌面控制獨立入口

桌面受管模式與 Local Work 選項已移到主畫面的「桌面控制…」。可在此啟用或停用桌面自動控制、開啟受管桌面及恢復已暫停的程式。桌面狀態與程序提示也統一使用「桌面控制」名稱。

VS Code 另有「VS Code 整合…」入口，維持可選的實驗整合。這次調整入口與顯示文字，保留既有閒置、正常退出、程序身分與 Local Work 版本驗證；沒有新增自動續聊行為。以下保留各版本的實作與驗證紀錄；舊紀錄提到的桌面「實驗整合…」入口，目前請使用「桌面控制…」。

## v1.4.6：可選封鎖受管桌面的 Local Work

桌面 App 可能另外啟動 Local Work 的獨立本機執行器。這個程序與受管對話後端分開；即使對話已閒置，無法查詢工作狀態的獨立執行器仍會阻擋帳號切換。

不使用 Local Work 時，可在「桌面控制…」勾選「受管桌面封鎖 Local Work（重新啟動後生效）」，完成目前工作並正常 Quit，再由切換器開啟受管桌面。此選項預設關閉，只作用於之後的受管啟動。封鎖後 Local Work 無法使用，App 可能顯示相關設定錯誤；一般從開始功能表啟動的 App 保持原本行為。

封鎖需通過已安裝 App 版本驗證；版本不符時會停止受管啟動。現有對話與程序不會因勾選選項而被關閉，帳號套用仍須通過所有閒置、正常退出與程序檢查。尚未驗證真實跨帳號切換與自動續聊。

## v1.4.5：修正桌面握手就緒條件

修正桌面 App 已載入，切換器卻一直顯示「尚未確認準備完成」的問題。桌面 App 在成功初始化回覆後就完成握手，不會送出額外的 `initialized` 通知；桌面受管模式現改為確認成功回覆已轉送。VS Code 的通知要求維持原本規則。

「後端已連線」與「已確認可安全切換」分別判斷：啟動等待使用連續三秒的新鮮連線狀態；真正套用帳號仍須可靠的工作狀態、閒置、正常退出與程序檢查。工作狀態未知時會說明尚待確認的原因，繼續阻止切換。

新增 `--desktop-diagnostics` 唯讀診斷模式，只查詢整合狀態，將不含帳號、路徑、程序識別或對話的摘要寫入本機私人 `integrations/desktop/diagnostics/latest.json`，方便後續查明問題。

更新後請重新開啟切換器，在「實驗整合…」開啟受管桌面，完成目前工作並正常 Quit，讓新版協調器接續。

本版 C# 回歸 **237／237**、companion 合成測試 **9／9** 通過。真正隨附 CLI 的隔離對照確認：不送通知時，舊條件一直停在 initializing，新桌面條件可正常確認連線並查到可靠閒置。原生 WebSocket 回歸也涵蓋相同的無通知握手流程。

## v1.4.4：修正桌面整合記錄讀寫競態

修正「無法驗證桌面整合記錄」的並行讀寫問題。讀取改用允許檔案替換的固定 Handle，從同一個檔案驗證擁有者、ACL、類型及大小，再讀取完整 UTF-8；短暫的檔案替換間隙會有限重試。格式、安全檢查及大小限制仍維持。

### 啟用桌面控制（目前版本）

1. 開啟切換器，確認主畫面的桌面控制為「已開啟」。新設定預設開啟；若先前關閉，可在「桌面控制…」勾選「開啟桌面自動控制（記住此設定）」。工具會保存選擇，重新開啟後沿用並自動接續啟動。
2. 若已有受管桌面連線，工具沿用它；若顯示等待正常退出，請保持切換器開啟，完成工作，再從 Codex 選單或系統匣選「結束 ChatGPT／Quit」，並正常結束畫面列出的其他 Codex 工作。相關程序穩定退出後才會開啟受管桌面；只按右上角 X 可能仍留有背景程序。
3. 使用「檢查工作狀態」確認實際連線及工作狀態。開關已開啟不代表已連線或閒置；之後也可從桌面控制視窗按「開啟受管桌面」，或由切換流程恢復。從開始功能表另行開啟的實例仍視為未受管。

若不使用 Local Work，啟動前可勾選「受管桌面封鎖 Local Work（重新啟動後生效）」。這會讓下一次受管桌面的 Local Work 無法使用；已有桌面須先正常 Quit，再由切換器開啟。取消勾選也在下次受管啟動生效。

工具會先共同檢查桌面與 VS Code 狀態。確認可安全處理後，桌面整合先凍結新連線與新工作，逐一準備所有受管後端，再次核對狀態與連線代次，才提交 stdin EOF 並等待 exit code 0。之後核對 App 的 PID、建立時間、執行檔、Windows 使用者與工作階段，以 Restart Manager 的非強制關閉要求退出該 App；通過程序安靜檢查後才套用登入。恢復會重新開啟受管 App，VS Code 則由 companion 要求對應視窗重載。**兩者都不會自動送出聊天訊息或接續對話。**

桌面整合只等待閒置，不會中止忙碌回合。狀態未知、背景工作未結束、未受管程序、控制已停用或身分變更，都會阻擋帳號套用。等待時可取消；若退出已部分完成而無法安全恢復，請依提示正常 Quit，再使用「恢復已暫停的桌面／VS Code」。沒有可用主視窗、App 拒絕關閉或退出逾時時，不會改為強殺。Restart Manager 的 end-session 與 exit code 0 也不代表 Electron 的完整 Quit／flush 已獲驗證。

受管啟動沿用目前的 `CODEX_HOME`、桌面 profile 與 SQLite 位置；已設定的 `CODEX_ELECTRON_USER_DATA_PATH`、`CODEX_SQLITE_HOME` 須為絕對路徑。不會以新的空 profile 取代平常的聊天與設定。此整合限可解析的 Windows 桌面套件，不支援既有外部 `CODEX_APP_SERVER_WS_URL`、`CODEX_APP_SERVER_FORCE_CLI=1`，或指向套件外 CLI 的 `CODEX_CLI_PATH`。這些啟動介面有版本相依性，更新後若無法驗證就停止切換。

關閉「開啟桌面自動控制（記住此設定）」會保存關閉選擇並撤銷自動退出與恢復授權，停止後續自動啟動；重新開啟工具也維持關閉。現有一般對話轉送可繼續，工作完成後請正常 Quit，再從開始功能表啟動。首次啟用、啟動失敗或取消等待本身不會變更登入帳號。

恢復會先確認啟動要求已接受，再持續查詢新後端是否就緒，最多等待兩分鐘；就緒前、逾時或停用時，會保留可重試的恢復記錄。若持續顯示未知，請先正常 Quit，再關閉「開啟桌面自動控制（記住此設定）」，等相關程序正常退出後重新開啟。

## v1.3.0：自動監看與可選 VS Code 整合

### 啟用 VS Code 實驗整合

此整合可選用，限本機 Windows 原生 Codex 後端；不支援 Remote / WSL 視窗。安裝擴充套件本身不會啟用控制。

1. 在切換器按「VS Code 整合…」中的「開啟整合安裝檔位置」，或找到 `dist-v1.6.0\codex-account-switcher-vscode.vsix`。
2. 在 VS Code 命令選單執行 `Extensions: Install from VSIX…`，選取該檔案。
3. 執行 `Codex Account Switcher: Enable Experimental Integration`，選取同一發行資料夾的 `ManagedBridge.exe`，閱讀並確認實驗功能說明。
4. 等目前工作完成後，按 `Reload Window` 重新載入該視窗。首次啟用必須重新載入，新的 Codex 後端才會由整合管理。

整合使用官方擴充套件標示為開發用途的 `chatgpt.cliExecutable` 設定。它具有 **application scope**，其他視窗或設定檔下次啟動時也可能受影響；其他尚未整合或無法確認狀態的視窗仍會阻擋切換。重載會影響整個對應 VS Code 視窗的擴充套件狀態與未送出的 Codex 草稿，並非只重載單一聊天。

預設等待已整合的工作閒置，包含進行中的回合、等待處理的請求與背景 terminal。若希望切換時先正常中止回合，須在自動監看時另外勾選「自動監看切換時允許正常中止回合（僅限已整合的 VS Code）」。手動切換會等待目前回合結束。中止不會撤銷已完成的操作，也不會跳過仍在執行的背景工作。工具不會強殺 `Code.exe`、共用擴充套件宿主或其他外部程序。

確認閒置後，整合會關閉自己持有的後端輸入並等待正常退出；切換後由 companion 重新載入對應視窗恢復 Codex。**恢復不會自動送出訊息或接續對話**。若恢復未完成，可在「桌面控制…」按「恢復已暫停的桌面／VS Code」；它只處理已驗證、屬於相同登入快取且已閒置暫停的後端。仍未恢復時，依提示手動重新載入並確認登入帳號。

停用時執行 `Codex Account Switcher: Disable Experimental Integration`。它會立即撤銷自動中止／暫停的授權，並在設定仍指向整合程式時還原原值；一般對話轉送會繼續。停用不會自動重載，待工作完成後可自行按 `Reload Window`；已暫停的後端也需重新載入才能恢復。

這項整合已在隔離的真實 VS Code 視窗，搭配官方 Codex 擴充套件與合成模型回覆，通過回合正常中止、後端自然退出、companion 重載及新後端恢復閒置驗證。**原對話是否恢復尚未確認，真實登入套用與跨帳號續聊尚未驗證**。詳細範圍見 [控制介面驗證](docs/runtime-control-validation.md)。

## v1.1.0：各帳號的剩餘額度

已儲存的帳號會各自顯示「5 小時上限」與「每週上限」的剩餘百分比、進度條、重設時間及最近查詢時間。開啟工具、儲存目前帳號或新增帳號後會查詢；也可按「更新全部額度」或「重新整理」手動更新。查詢期間可取消，不會切換目前的 Codex 登入。

資料來自官方 [App Server 的 `account/rateLimits/read`](https://learn.chatgpt.com/docs/app-server)。依服務提供的視窗長度區分 5 小時與每週，剩餘量為 `100 - usedPercent`；重設時間以目前電腦時區顯示。未提供的額度會標示「未提供」，不視為無限、0% 或 100%。這些是查詢當下的快照；到達預計重設時間後仍需重新查詢，不會自行推算額度恢復，也不代表其他模型或工作區限制已解除。

這項功能需要支援上述介面的 Codex CLI／桌面版。憑證過期、網路錯誤、服務拒絕或版本不支援時，個別帳號會顯示提示；若提示登入失效，請用「新增帳號」重新登入同一帳號後再查詢。每個帳號的查詢最多等待 30 秒，不會為了取得額度自動執行帳號切換或使用額度重設點數。

## v1.0.2 更新

修正「結束 ChatGPT 後持續等待，手動開啟仍是原帳號」時提示不明確的問題。若 VS Code 的 Codex 擴充功能仍在執行，切換器會等待它退出，尚未進入帳號套用步驟。新版會區分並列出桌面 App、VS Code、其他 IDE、CLI 或未知程序，以及 PID 和應關閉的來源。

等待中的帳號尚未套用，請等工具完成，不要先手動重新開啟 Codex。等待最多 5 分鐘，寫入前逾時或取消都不會進入套用步驟。未整合程序與已整合的 Codex 後端退出後，需通過一秒安靜期與再次檢查，才會保存、套用、讀回核對並啟動。工具不會強制關閉 VS Code；v1.3.0 的正常中止須另行啟用。

更新時，先取消舊版等待並關閉舊版切換器，再開啟根目錄的 `Codex帳號切換器.cmd`；它會啟動目前版本，帳號庫沿用。

## v1.0.1 更新

修正自動開啟桌面 App 出現「處理程序沒有套件識別資料」的問題。Microsoft Store / MSIX 安裝現在會從套件資訊解析正確的 Application ID，交由 Windows `IApplicationActivationManager` 啟動，保留套件身分；啟動失敗時不會再直接執行套件內的 EXE。一般非套件程式仍使用原本的 EXE 啟動方式。

此修正已包含在 v1.0.2。已儲存帳號會沿用，不需重新新增。

## 使用方式

1. 開啟工具，按「儲存目前帳號」收藏正在使用的 ChatGPT 帳號。主畫面另顯示桌面控制開關與連線狀態；開關選擇會保存，已開啟時會自動確認或等待啟動受管桌面，已關閉時維持關閉。
2. 按「新增帳號」，在官方瀏覽器登入頁選擇另一個帳號。若瀏覽器自動選到原帳號，在登入頁切換使用者。新增帳號不會更動目前 Codex 登入，需再按「切換並開啟 Codex」才會套用。
3. 可先使用「上移／下移」排列優先順序，再手動選取帳號或按「選取優先可用帳號」，最後按「切換並開啟 Codex」。
4. 依工具顯示的來源完成退出。已啟用桌面控制的 App、或已整合的 VS Code 可由工具等待閒置並正常暫停；未受管的桌面 App 須從選單或系統匣正常 Quit。**未整合的 VS Code** 則需先儲存工作，再自行關閉相關視窗，或停止其 Codex 擴充功能直到對應程序退出，並結束仍在執行的 Codex CLI。**只按視窗右上角 X 可能仍留在系統匣。** 通過退出檢查後，工具會套用帳號並開啟桌面 App／恢復已整合的視窗。
5. 在 Codex 的帳號選單確認切換結果。需要返回時按「切回上一個」。

「重新命名」可標記個人、工作、研究等用途。「移除」只移除此工具保存的帳號及其復原副本，不會登出目前 Codex，也不會撤銷伺服器上的登入。「取消」可中止等待切換或新增登入。登入逾時為 10 分鐘。

## 支援範圍

- 支援 `CODEX_HOME\auth.json` 的 ChatGPT 登入快取；未設定 `CODEX_HOME` 時使用 `%USERPROFILE%\.codex\auth.json`。
- 使用同一快取的 CLI / IDE 會跟著變更帳號，同一時間使用同一個登入帳號。
- 會辨識此電腦目前的 OpenAI.Codex 桌面套件，即使程式名稱已變為 ChatGPT.exe。
- 帳號切換的來源快取不支援 keyring / auto / ephemeral 儲存、API Key、外部存取權杖與受管理的特殊登入流程。遇到已辨識的不相容設定會停止套用；組織政策仍由 Codex 自身執行，本工具不修改政策。
- 帳號清單使用本機憑證中的顯示資訊，沒有驗證遠端登入有效性。存取權杖到期通常由 Codex 自行更新；已撤銷或失效的登入需用「新增帳號」重登。相同帳號的新登入會顯示「新登入，待套用」。
- 切換只更換登入快取，聊天、專案與設定沿用原本的本機資料；各帳號的雲端資料可見性由 Codex 決定。
- 此工具為獨立實作，沒有修改或注入 Codex 桌面 App，也不是官方多帳號 API。未保證日後版本仍採用相同快取格式。

## 本機資料

帳號、名稱、優先順序、登入憑證與上一個登入的復原資料，會以 Windows DPAPI 加密後存於：

`%LOCALAPPDATA%\CodexAccountSwitcher\accounts.dpapi`

帳號庫僅供建立它的 Windows 使用者使用，不能直接搬到其他使用者或電腦。

桌面控制的開關選擇、控制授權設定與工作階段紀錄存於同一資料目錄下的 `integrations\desktop`，限目前 Windows 使用者存取。開關選擇和目前是否已授權、連線分別保存與判斷；紀錄包含程序身分與工作狀態，不保存聊天內容。

續聊記錄另以 DPAPI 加密保存於同一資料目錄下的 `integrations\continuation`，包括帳號識別、原對話／回合識別、模型與權限設定、工作目錄、工具能力摘要、指令雜湊及送出狀態，不保存提示詞原文、工具輸出或登入憑證。這些本機資料有私人存取權限。

切換前，工具會保存最新登入與復原副本；備份失敗或偵測到 Codex 仍在執行時會停止。若無法自動啟動桌面程式，可從開始功能表手動啟動。

## 開發與驗證

在專案目錄執行 `powershell -ExecutionPolicy Bypass -File .\build.ps1`，使用 Windows 內建的 .NET Framework C# 編譯器。沒有 NuGet 相依套件。主要原始碼為 `Core.cs`、`DesktopLauncher.cs`、`ProcessInspector.cs`、`SwitchWorkflow.cs`、`App.cs`、`UsageModels.cs`、`UsageSession.cs` 和內嵌的 `MainWindow.xaml`；自動切換與 VS Code 整合位於 `AutoSwitchController.cs`、`ManagedRuntimeClient.cs`、`ManagedBridge.cs` 及 `integrations/vscode`。桌面整合位於 `DesktopRuntimeCoordinator.cs`、`DesktopSession.cs`、`DesktopHostProgram.cs`、`DesktopNative.cs`、`DesktopWebSocket.cs`、`DesktopAppRelay.cs` 及 `desktop-start.ps1`。桌面續聊由 `DesktopContinuationWorkflow.cs`、`DesktopConversationClient.cs`、`ContinuationTicket.cs` 與 `ContinuationAdmission.cs` 處理。程序診斷使用 Windows WMI 與原生 API，只讀取程序名稱、PID、父程序、工作階段、建立時間及執行檔路徑；受管整合另核對管線與 TCP peer 的擁有者，不讀取命令列或記憶體內容。無法確認程序狀態時停止切換。

驗證全新 Git 下載與建置（需要 Git；不會開啟 Codex 或帳號切換器視窗）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-CleanClone.ps1
```

此測試建立只含原始碼的暫存 Git repository，再 clone 到含空白與中文的路徑，從其他工作目錄執行真正啟動器的 `--build-only` 模式，檢查完整發行檔、VSIX 內容、快取及缺檔重建。它保留暫存結果供檢查，不讀取真實登入，也不會停止現有程序。這能驗證下載後不依賴原電腦的建置產物，不能取代另一台實體電腦的 Codex 連線驗收。

執行假帳號測試（不會讀取或修改真實登入）：

```powershell
$report = Join-Path $PWD 'test-results.json'
$test = Start-Process -FilePath .\tests\bin\CodexAccountSwitcher.exe -ArgumentList '--self-test', ('"{0}"' -f $report) -WindowStyle Hidden -PassThru -Wait
Get-Content -LiteralPath $report
```

測試必須在已載入 Windows 使用者設定檔的一般環境執行；某些沙盒無法使用 DPAPI。涵蓋加解密、重複帳號與工作區、憑證更新、新登入覆蓋舊登入、復原、程序執行阻擋、競爭更新、設定限制、備份寫入失敗、JSON-RPC 模擬登入及取消清理。

測試也涵蓋套件啟動目標解析、版本升級後的啟動識別、程序來源分類，以及完整等待協調流程（包括 VS Code 殘留、程序重新出現、取消、逾時、診斷失敗及套用失敗不啟動）。

排序測試涵蓋上下移動、邊界、舊帳號庫相容、新增／改名／重登後順序，以及儲存失敗時回復原序。額度測試涵蓋只有每週上限、格式異常、過期與重設邊界、按順位挑選及真實 WPF 按鈕行為。

v1.3.0 另驗證單一監看流程、目前帳號耗盡才查候選、依順位選取、退出後重查、狀態變更／取消阻擋寫入與恢復失敗處理。v1.3.0 的 C# 回歸測試 124／124 通過，包含暫停被拒且後端仍在執行時不誤觸重載的修正。Bridge 的 6 組真實 Named Pipe＋模擬後端測試及 companion 的 9 組獨立模擬測試均通過；另外已驗證隔離 VS Code 視窗內的合成回合中止、正常退出與重載恢復。

測試使用虛構帳號與獨立目錄；實際 VS Code 視窗驗證使用預先配置的隔離整合及本機合成模型服務，未使用真實登入。重載後的新後端與編輯器分頁已恢復，但原對話是否恢復尚未確認，真實帳號切換後的登入與跨帳號續聊尚未驗證。v1.4.0 只對受管且已確認閒置的桌面實例要求非強制退出，不會自動中止桌面回合或送出續聊訊息。詳細範圍見 [控制介面驗證](docs/runtime-control-validation.md)。
